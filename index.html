Is the edge real? (permutation test)

Real vs. shuffled: what actually differs

The permutation shuffle keeps the same multipliers and the same funding mode — only which month each one lands on changes. If the real run and the shuffled average agree on invested/deployment rate but disagree on BTC, the edge is timing; if they disagree on invested/deployment rate too, some of the "edge" is really just funding starvation working differently under shuffling.

08b Deployment-ratio sweep

Diagnostic workflow: under strict funding, sweep target deployment for the benchmarked strategy from 1.0 down to 0.5 and watch the permutation p-value (not the return). If p stays high throughout, the multiplier's shape isn't producing a timing edge, whatever the funding constraint. If p drops sharply as target deployment falls, the strategy needed unmet demand (starvation) to look non-random — the funding constraint was doing the work.
